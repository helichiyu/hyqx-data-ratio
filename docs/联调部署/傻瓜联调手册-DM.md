# DM 数据配比 · 傻瓜联调手册

> 适用：本机前后端 + 算法三端联调。
> 原则：**每步只做一件事，看到「成功标志」再进下一步；不对就查最后的问题对照表。**
> 本手册只覆盖本地独立壳；主应用/UAP 菜单授权见最后的「主应用联调」一节。

---

## 0. 开始前准备

| 项 | 内容 |
| --- | --- |
| 前端 | `http://localhost:9851/#/data-mixing/dataset/index` |
| 后端 | `http://127.0.0.1:8082/hs-api` |
| 算法 | `http://127.0.0.1:8092` |
| 浏览器 | Chrome / Edge，F12 打开 Network 备用 |
| 账号 | 本地 `local-dev` 模式不用登录；主应用联调才需要平台账号 |

### 0.1 三端怎么启动

三个窗口分别执行（推荐 CMD，直接复制）：

```bat
:: ① 后端
cd /d D:\Project\hyqx\hyqx-data-ratio\hsmty-module-dm-server && set DM_ALGORITHM_ENABLED=true && set DM_ALGORITHM_BASE_URL=http://127.0.0.1:8092 && "C:\Program Files\Java\jdk-21\bin\java" -jar hsmty-module-dm-start\target\hsmty-module-dm-start.jar --spring.profiles.active=local-dev --server.port=8082 --spring.liquibase.enabled=false --spring.threads.virtual.enabled=false
```

```bat
:: ② 算法（权重和依赖要先准备好，见 0.2）
cd /d D:\Project\hyqx\hyqx-data-ratio\operator && set PORT=8092 && set DEVICE=cpu && set MODEL_BACKEND=idg && set MAX_UPLOAD_BYTES=1073741824 && ..\.venv-operator\Scripts\python.exe inference.py
```

```bat
:: ③ 前端
cd /d D:\Project\hyqx\hyqx-data-ratio\hsmty-web && corepack pnpm dev
```

> PowerShell 把 `&&` 换成 `;`；也可以直接让 Claude 帮你启动三端。

### 0.2 算法权重/依赖（打标和 basic 画像的前提）

- `operator\weights\shared\` 必须是**有文件**的，不能只有 `.gitkeep`；
- 需要 bge-base-zh-v1.5、paraformer-zh、fsmn-vad、ct-punc 等权重；
- Python 依赖按 `operator\requirements.txt` 安装（`torch`、`transformers`、`funasr` 等）；
- 音频/视频还需要 ffmpeg。

> 当前本机 `operator\weights\` 是空的，所以：
> - `quality/language/text` 画像可以先跑；
> - **打标和 basic 画像会明确失败**，这是缺权重，不是页面 bug。

### 0.3 三个健康检查

```bash
curl -s -o /dev/null -w "backend=%{http_code}\n" http://127.0.0.1:8082/hs-api/actuator/health
curl -s -o /dev/null -w "algorithm=%{http_code}\n" http://127.0.0.1:8092/health
curl -s -o /dev/null -w "web=%{http_code}\n" http://localhost:9851/
```

预期：`backend=200`、`algorithm=200`、`web=200`。

# 第一部分：10 分钟快速通道

## 第 1 步：打开页面，看左侧菜单

打开：

```text
http://localhost:9851/#/data-mixing/dataset/index
```

左侧应该出现：

```text
数据工程
├── 数据治理
│   ├── 数据接入与标准化
│   ├── 分类体系管理
│   ├── 数据打标
│   └── 语料画像分析
├── 配比生产
│   ├── 场景管理
│   ├── 配比方案设计
│   ├── 配方包管理
│   ├── 配比生产任务
│   └── 配比分析任务
└── 质量与合规
    └── 风险预警
```

✅ **成功标志**：菜单完整，点「数据接入与标准化」页面能加载，不白屏。

❌ 左侧空白 → 看问题对照表第 1 条。
❌ 页面白屏 → 看问题对照表第 2 条。

## 第 2 步：数据接入与标准化

1. 点「数据接入与标准化」。
2. 看列表里有没有 **算法联调-文本-20261118**。
   - 有：直接点「文件」确认有 `machine_learning.jsonl`；
   - 没有：点「新建批次」→ 名称随便填 → 来源「本地上传」→ 模态「文本」→ 文件格式 `jsonl` → 确定；再点行内「上传」，拖入 `docs\算子开发\samples\text\machine_learning.jsonl`；最后点「启用」。
3. 点「文件」→ 点「下载」，文件能打开。

✅ **成功标志**：列表有数据集，文件数 1，大小非 0，状态「可用」。

## 第 3 步：语料画像分析（先跑 quality）

1. 点「语料画像分析」。
2. 数据集选「算法联调-文本-20261118」。
3. 画像类型先只选 **质量与一致性**。
4. 点「创建并启动」。
5. 等 20–60 秒。

✅ **成功标志**：

- 任务状态「已完成」；
- 上方画像卡出现摘要；
- 点「查看结果」能看到指标数和 JSON，并有难度/极性图表。

> 选 **规模/来源/领域（basic）** 会先跑 OP-06，需要 bge 权重。
> 没有权重时它会明确失败：`DEPENDENCY_UNAVAILABLE ... bge-base-zh-v1.5`，这是预期。

## 第 4 步：数据打标

1. 点「数据打标」。
2. 点「新建任务」→ 数据集选「算法联调-文本-20261118」→ 打标方式「自动」→ 置信度默认 0.25 → 立即启动打开 → 确定。
3. 等 10–30 秒。

✅ **有权重时**：状态「已完成」，详情里能看到样本和标签。

❌ **没权重时**：状态「失败」，原因 `DEPENDENCY_UNAVAILABLE ... bge-base-zh-v1.5`。这是预期，不是页面 bug。

## 第 5 步：分类体系（草稿版本才能编辑）

1. 点「分类体系管理」。
2. 默认看到的是「生效版本」，顶部会有提示：**只读**。
3. 点「版本管理」→「新建版本快照」：
   - 版本名称：`联调草稿-你的名字`
   - 立即生效：**关闭**
   - 确定。
4. 创建后会自动切到这个草稿版本（顶部版本下拉变了）。
5. 现在点「新增根节点」→ 名称 `联调节点-你的名字` → 确定。
6. 节点出现后，点「编辑」改个名字；点「停用/启用」。
7. 点「版本管理」→ 对这个草稿点「设为生效」。
8. 再新建一个草稿，点「删除」，确认能删。

✅ **成功标志**：

- 生效版本不能新增/编辑/删除（按钮隐藏，顶部有只读提示）；
- 草稿版本能新增、编辑、启停；
- 版本能切换、能删除非生效版本。

## 第 6 步：场景管理

1. 点「场景管理」→「新建场景」。
2. 名称：`联调场景-你的名字`。
3. 模型定位「通用基座」，训练阶段「微调」。
4. 应用场景输入 `对话交互` 后回车。
5. 分类树只勾 **1 个根节点**（例如「信息与资讯」）。
6. 核心占比下限 30，覆盖目标 100，确定。

✅ **成功标志**：列表出现场景，状态「启用」。

> 勾父节点不会自动勾子节点，这是故意的；配比覆盖校验按路径前缀匹配。

## 第 7 步：配比方案设计

1. 点「配比方案设计」→「新建方案」。
2. 名称 `联调方案-你的名字`；场景选第 6 步的场景；目标总量 `100000`。
3. 点「添加行」两次：
   - 第 1 行：标签路径选第 6 步勾选的根节点，比例 60，角色「核心」；
   - 第 2 行：选另一个标签，比例 40，角色「通用」。
   - 右上角应显示「比例合计 100.000%」。
4. 保存。
5. 点该行「详情」→「校验」→「生成推荐」。
6. 关闭详情，点该行「启用」。

✅ **成功标志**：保存成功、校验通过、状态「已启用」。

❌ 报“核心标签占比低于下限” → 第 1 行角色没选「核心」或比例不到 30。
❌ 报“场景标签覆盖率不足” → 方案行里没有包含场景勾选的标签。

## 第 8 步：配方包管理

1. 点「配方包管理」→「新建配方包」。
2. 名称 `联调配方-你的名字`；配比方案选第 7 步的方案；确定。
3. 点该行「版本」→「生成新版本」→ 变更说明随便填 → 确定。
4. 点版本行「发布」。
5. 点「仿真」→「发起仿真」。

✅ **成功标志**：

- 版本状态「已发布」；
- 仿真任务 10–30 秒内「已完成」；
- 结果里能看到六维能力/达成度/建议。

## 第 9 步：配比生产任务

1. 点「配比生产任务」→「新建生产任务」。
2. 配方包选第 8 步的配方；配方版本选已发布版本；**数据集选第 2 步的数据集**；立即启动打开；确定。
3. 看状态。

✅ **已有打标样本时**：任务完成，详情里「阶段产物」能下载 zip。

❌ **没有打标样本时**：任务失败，原因“请先完成数据集【...】的数据打标并产出样本”。这是预期。

## 第 10 步：配比分析任务

1. 点「配比分析任务」→「新建分析任务」。
2. 分析类型选 **报告生成**；数据集选第 2 步的数据集；立即启动打开；确定。
3. 等任务完成，点「结果」。
4. 选报告格式 HTML，点「生成报告」→「下载」。

✅ **成功标志**：

- 报告任务「已完成」；
- 能看到指标结果；
- HTML 报告能打开。

> 「九维分析/配比分析」需要先有成功的生产任务；没有生产时用「报告生成」即可。

## 第 11 步：风险预警

1. 点「风险预警」。
2. 方式一：点「登记风险」→ 标题/类型/等级随便填 → 确定 → 点「处置」→ 选状态 → 确定。
3. 方式二：点「从画像生成风险」→ 选第 2 步的数据集 → 生成。

✅ **成功标志**：

- 手工风险能新增、处置；
- 从画像生成时提示“已生成 N 条风险”或“没有发现新的风险”；
- 列表和 KPI 同步刷新。

# 第三部分：问题对照表

| 现象 | 大概率原因 | 怎么办 |
| --- | --- | --- |
| 左侧没有菜单/空的 | 前端没启动，或本地壳菜单回退失败 | 确认 9851 打开；Ctrl+F5；仍不行发 F12 Console 截图 |
| 页面白屏 | 前端编译错误/资源没加载 | 看 Vite 窗口报错；重新 `corepack pnpm dev` |
| 接口 302/401 | 后端没加 `local-dev`，或主应用 Cookie 过期 | 本地壳启动加 `--spring.profiles.active=local-dev`；主应用重新登录 |
| 接口 403 | 主应用角色没授权 DM 菜单/资源 | UAP 给角色授权；本地 `local-dev` 不应出现 |
| 打标失败 `DEPENDENCY_UNAVAILABLE` | 缺 bge 权重 | 准备 `operator\weights\shared\bge-base-zh-v1.5` 后重启 8092 |
| basic 画像失败 `DEPENDENCY_UNAVAILABLE` | basic 先跑 OP-06，缺 bge 权重 | 同上；先测 quality 画像 |
| 任务一直「运行中」 | 后端连不上算法，或算法没启动 | `curl http://127.0.0.1:8092/health`；看后端窗口报错 |
| 任务失败 | 看页面「失败原因」 | 按原因处理；权重/依赖问题找算法侧 |
| 分类树不能新增/编辑 | 当前是生效/归档版本 | 先「版本管理」建草稿，再在顶部选草稿 |
| 配比方案保存失败 | 比例不是 100 / 核心 <30 / 场景标签没覆盖 | 按页面提示补行或改角色 |
| 生产失败“先完成打标” | 该数据集没有已完成打标任务 | 先打标；打标需要权重 |
| 分析九维失败“先完成生产” | 九维依赖生产 plan | 先跑生产，或改用「报告生成」 |
| 报告按钮禁用 | 任务还没有 analysis_result | 等任务 completed；失败时先看原因 |
| 风险从画像生成为 0 条 | 画像结果未完成，或没有触发规则的指标 | 先完成 quality/basic 画像；0 条也可能是数据正常 |

## 报告问题时请带上

1. **第几步**（例如“第 4 步：数据打标”）；

4. 如果是接口问题：F12 → Network → 失败请求的 URL、状态码、Response。

# 第五部分：本轮不做的功能

如业务要求这些，需要另立任务单，不在本次联调范围。
