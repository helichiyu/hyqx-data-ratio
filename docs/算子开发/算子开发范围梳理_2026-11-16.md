## 0. 结论摘要

1. **原型共 11 个页面，其中 8 个页面含算子能力**：数据接入、数据打标、语料画像、配比方案、配比生产、配比分析、风险预警、工具链。其中前 7 个以算子为主；风险预警以平台流程为主，只含规则算子。分类体系、场景管理、配方包管理以平台 CRUD/流程为主。
2. **算子能力约 57 项，建议按 8 个能力域组织**。其中 P0（打通最小真实链路）22 项，P1 29 项，P2 6 项。这里的「项」是能力点，不等于 57 个独立部署；按模型栈可收敛为 15～20 个算子服务/算子 tag。
3. **工作量重心不在「配比」本身**。12.x 的配比主要是规则/统计算子（加权占比、覆盖率、库存、达成度）；真正重的是：
   - **13.1 多模态解析与标准化**（文本/图像/音频/视频四套解析栈）；
   - **12.2 四模态自动打标 + 领域/能力多标签**；
   - **13.2/13.3 语料画像与技术属性分析**（约 15 类指标、20+ 个模型/算法）。
4. **原型当前几乎全部是假数据**：模态识别用批次名哈希，进度条用 `Math.random()` / `setInterval`，画像指标全部是常量数组，配比角色系数是写死的乘数，能力预测用硬编码 fit 向量，9 维分析报告由常量表 + 随机分拼成，工具链健康度/专家任务均为常量。详见附录 A。
5. **必须先划清平台边界**：语料存储、元数据/结果库、任务编排、人工审核、权限、通知、进度展示、报告下载入口、Neo4j/FAISS 服务运维都不属于算子。没有这些平台能力，算子无法单独验收（详见第 5 节）。
6. **建议的最小真实链路**：
   `接入 → 模态识别 → 四模态解析 → 标准化/元数据/去重 → 句向量+聚类 → 分层抽样 → 自动打标 → 画像统计 → 配比计算/校验 → 组装选样/打包 → 评测 → 分析报告`
   这条链路跑通之前，原型的任何「随机结果」都不能作为交付证据。

## 1. 判定口径：什么算「算子」

| 类型 | 定义 | 典型能力 | 部署形态 |
| --- | --- | --- | --- |
| 解析型 | 读原始文件、容器、编码，产出结构化内容/特征 | 文本/PDF 解析、图像 EXIF、ffprobe、抽帧 | CPU，文件契约 |
| 模型型 | 加载模型做分类/识别/抽取/打分 | 自动打标、语种识别、ASR、场景分类、NER、合规检测 | GPU/CPU，模型服务 |
| 规则型 | 确定性规则、阈值、加权、归一化、集合覆盖 | 配比校验、库存折算、标签合法性、风险分级、专家抽样 | CPU，JSON 契约 |
| 统计型 | 大规模聚合、分位数、熵、基尼、分布检验 | 规模结构、来源占比、主题覆盖、质量一致性 | CPU/Spark/DuckDB |
| 图与检索型 | 向量化、ANN、图谱抽取与查询 | BERT 向量、FAISS、Neo4j 图谱 | GPU/图数据库 |
| I/O 型 | 源库/对象存储增量拉取、断点续传 | JDBC keyset、S3 Range | 平台连接器，可下沉平台 |

**不算算子（平台/前端/人工）**：

- 分类树/领域树/能力树的增删改、启停、排序；
- 场景、配方包、任务、风险工单、专家校验任务的 CRUD 与状态机；
- 列表筛选、分页、弹窗、滑块、进度条、通知、权限、审计日志；
- 人工审核、人工归类、专家签署、处置动作；
- 对象存储写入、数据库落库、报告下载入口、图表渲染；
- 健康度面板、运维按钮（只触发算子，不实现算子）。

> 判定原则：**能否对真实语料产生可核验的新结果**。只能搬运/展示平台已有数据的，不是算子。

## 4. P0 最小真实链路与实现要点

### 4.1 链路

```
上传/接入批次
  → ING-01 模态识别
  → ING-02/03/04/05 四模态解析
  → ING-06 标准化 + ING-08 元数据索引（+ ING-09 去重）
  → SHP-01 句向量 + SHP-02 主题聚类
  → LBL-01 自动初标（文本/图像优先）
  → PRF-01/02/04/06/07/13 画像指标
  → RAT-01/02/03 来源占比、加权配比、规则校验
  → PRD-01 组装选样 + PRD-02 打包
  → PRD-03 评测
  → PRD-05 九维聚合 + PRD-06 报告
```

### 4.2 关键算子实现要点

**ING-01 模态识别**
- 真实输入：文件清单/对象存储前缀；只读前 64KB～1MB + ffprobe 流信息。
- 判定：magic number/MIME + 扩展名 + 编码探测 + 容器流；目录/归档按成员展开；视频带音轨、PDF 含扫描页按流/页拆分。
- 输出：`modal`、`confidence`、命中证据、每模态样本数/字节量、待人工确认清单。
- 算法：libmagic、ffprobe、chardet/uchardet；兜底 fastText，不用大模型。
- 验收：对 9 个接入批次逐文件判定，与人工标注比对；混合文件拆流后各模态计数一致。

**ING-02 文本解析**
- 真实输入：TXT/JSONL/JSON/XML/PDF；字段映射配置。
- 输出：`record_id/text/char_len` + 页号/段落/字号/bbox/heading；空文本率、乱码率、解析失败数。
- 算法：PyMuPDF + pdfplumber、lxml、orjson/ijson；扫描件 PaddleOCR + 版面模型。
- 注意：PDF 单独算子，避免 OCR 超时拖垮普通文本解析；按页/行分片，file-contract 回传 part 文件。

**ING-03/04/05 图像/音频/视频解析**
- 图像：Pillow 读 header + EXIF + ICC；OpenCV 可解码校验；WebP + phash。
- 音频：ffprobe + ffmpeg/soxr 16k mono + librosa 梅尔谱 + VAD；长音频 5-10 分钟切片。
- 视频：ffprobe + ffmpeg 分流 + 场景抽帧（PySceneDetect）；输出帧-时间戳-视频 ID 关联键，音轨转 ING-04。
- 验收：每模态抽 1% 文件做人工核对，属性抽取准确率 ≥99%；失败文件有原因码。

**ING-06 标准化 + ING-08 元数据**
- 标准 schema：`record_id, modal, source, text, metadata, quality`；Parquet row group 128MB、zstd。
- manifest 必含：输入指纹、算子版本、参数哈希、条数、成功/失败、输入/输出字节、压缩比。
- 元数据宽表：唯一 ID、原始格式、大小、MD5、处理状态、模态、来源、时间、分区路径、质量标记。
- 幂等：输出路径 = `hash(输入指纹 + 算子版本 + 参数)`；重跑覆盖同路径。

**SHP-01/02 句向量与主题聚类**
- 向量：按句/段 512 token 切分，bge-base-zh 或 bge-m3，L2 归一化，float16；输出 `sentence_id → vector` 与模型版本。
- 聚类：MiniBatchKMeans，K 在 8~64 / `sqrt(N/2)~4*sqrt(N)` 搜索，5 万样本估轮廓系数；输出最优 K、每簇规模、c-TF-IDF 主题词、参数快照。
- 验收：同一批数据固定 seed 重跑，K/轮廓系数/簇映射一致；抽样 20 簇人工看主题词是否可解释。

**LBL-01 四模态自动初标**
- 文本：BERT/RoBERTa-zh 层级分类，一级 softmax 后条件分类；长文本分块投票；置信度温度校准。
- 图像：ConvNeXt/ViT 微调 + CLIP zero-shot 长尾兜底；文档/证照先 OCR 判类型。
- 音频：PANNs/AST/CLAP 事件分类 + Whisper/Paraformer ASR + 语种/方言；音乐/人声先分离。
- 视频：关键帧 CLIP + 音轨 CLAP + ASR 文本三路融合，按场景时长加权投票。
- 输出：可变深度路径、置信度、topK、证据（文本 span/关键帧/时间段）、模型与树版本。
- 验收：与人工审核样本比对，初标准确率给出 Wilson 置信区间；低置信样本进入未归类池。

**PRF-01/07/13 画像核心指标**
- 规模：流式扫描分片，t-digest 分位数，UTF-8 字节；按模态分别输出。
- 文本属性：HanLP/LTP 依存句法；句长=词/句、从句深度=依存树深度、被动句规则；TTR/MSTTR/MTLD；体裁/语体分类。
- 质量：字段完整率、跨文档冲突（实体链接+属性比对）、基尼系数、低频实体（<5 次）、多模态 CLIP/ASR 对齐。
- 验收：每个指标给出口径、样本量、置信区间；与人工抽样标注比对，关键指标误差在约定范围。

**RAT-02/03 配比引擎**
- 权重链路：采样频率 × 来源权重 × 偏见降权 × 角色/阶段系数；有效条数 = 条数 × 权重；占比 = Σ有效条数 / Σ全部有效条数。
- 归一化：最大余数法，0.1% 精度，长尾不置零，单标签上下限约束；禁止把差额塞给第一行。
- 校验：高频核心标签加权占比 ≥30%；一级/二级类别覆盖 100%；合计 100%（容差 0.1%）；最小样本 10 万条；库存 = 目标% × 总规模 vs 真实可用 token。
- 输出：条数/权重/占比三列、校验单（pass/fail + 实测值）、未覆盖类别、缺口量。
- 验收：手工构造 10 条样本的极限用例，能复算每个占比；库存单位统一（token/条）并注明口径。

**PRD-01/02 组装与打包**
- 选样：按层（来源×主题×质量×难度）配额，Neyman 分配，加权无放回，固定 seed；输出样本清单与层偏差。
- 打包：流式读源文件，按 `modal/source/dt` 分区写 Parquet，逐条 MD5/SHA-256，manifest.jsonl，支持断点续跑。
- 验收：打包文件可被下游训练框架直接读取；manifest 条数/哈希与文件一致；重跑幂等。

**PRD-03 评测**
- 抽样：5-10% 分层抽样，高风险/关键指标全量纳入；输出抽样清单与置信区间。
- 标签准确率：按模态重新预测，与真值做路径精确/前缀匹配；输出总体/分模态/分层准确率、宏 F1、混淆矩阵、错标清单。
- 验收：与 12.2 自动打标共用同一模型与树版本，避免两套口径。

**TOL-04 专家抽样 / RSK-01 风险规则**
- 专家抽样：5-10%，Neyman 分层，高风险必选，哈希取模可复现；输出抽样方案与实抽比例校验。
- 风险规则：消费各指标算子结果，双阈值 + 作用域 + 最小样本量 + 去重/抑制；输出风险条目与证据引用；不重复计算指标。

## 6. 算子协议与工程约束

### 6.1 复用现有算子池协议

参考 PST/IND 已验证的协议，不另起一套：

- 端点：`/health`、`/uploadFile`、`/predict`、`/downloadFile`、`/removeFile`。
- 鉴权：`X-Token`；401/403 映射为独立 Auth 异常。
- 两种契约：
  - **file-contract-v02**：输入输出都是文件（Parquet/JSONL/图片/音频/视频），适合解析、打标、画像、打包、评测；
  - **phase-v2**：JSON 进 JSON 出，适合配比、校验、抽样配额、风险规则等轻量规则。
- 请求大小：单请求 10MiB 级上限 → **语料绝不能内联 JSON**，必须 `uploadFile` 后传路径/OSS ID；大文件按分片多次调用，由平台串联。
- 超时：解析/ASR/视频类按 20-30 分钟；规则类 5-30 秒；长任务必须支持幂等重跑与断点。

### 6.2 算子 tag 与 ID

- 语义编码建议：`corpus_ingest_text_parse_v1`、`corpus_label_multimodal_v1`、`corpus_profile_source_credibility_v1`、`ratio_weighted_plan_v1`、`prod_assembly_sample_v1`。
- 业务编号按平台 ID 规范：`OP` + `yyMMdd` + 6 位随机码（如 `OP261116A3F9KX`），语义编码作为算子调用编号，发布后不可改。
- 每个算子返回 `operatorVersion`、`modelVersion`、`treeVersion`、`paramsHash`，便于结果追溯与复算。

所有算子结果至少包含：

### 6.4 算力与模型建议（可替换，供选型讨论）

- 文本分类/语种/NER：BERT/RoBERTa-zh、bge-m3、fastText；CPU 可跑，GPU 更快。

- 数据集可视化分析与报告管理（画像/报告）
- 数据集包生成任务管理（配方包/组装/投喂）
- 手动定制生成数据集包（配比方案设计）

原型**未覆盖或只部分覆盖**、需要确认是否在本次范围：

- **数据配比策略仿真与准入管理**（候选策略、沙盒仿真、七维评估、训练准入、放行闭环）；
- **智能推荐生成数据集包**（业务目标画像、语义拆解、需求推导、多方案推荐、反馈迭代）；
- **参考配方相似生成数据集包**（参考集画像拆解、复刻规则、双集对标）；
- **数据集包配比分析管理**（子集权重、主题互补/冗余、跨子集关联、配比行业基准等 40+ 项）；
- **数据集包可视化分析与版本管理**（多版本差异、综合评估图谱、交付血缘）；
- **数据配比数据统计**（运营指标看板）。

如果这些也要交付，算子清单需再加「策略仿真、目标语义拆解、推荐优化、参考集复刻、子集互补/冗余分析、版本差异评估」等能力，建议单独立项，不与本次原型链路混排。

## 9. 待确认问题

1. **算力与模型**：是否提供 GPU 池？文本/图像/音频/视频模型是否由算法组统一提供，还是算子组自选？
2. **分类体系权威源**：`【分类体系】分类体系结构-1013-zsy.xlsx`、原型树、Comic 任务书三者不一致时以谁为准？树需要版本化（`treeVersion`）。
3. **数据源口径**：FGW 六类（网络文本/书籍/代码/科学文献/维基/对话）与原型三类（移动内部/外部/合成）如何映射？是否需要同时保留两套标签？
4. **阈值口径**：30%、100%、10 万条、基尼 0.6、WER 20%、新鲜度 0.4、语种置信度 0.85，是固定值还是平台可配置？需业务书面确认。
5. **人工审核数据**：打标准确率、专家一致性必须有历史人工审核记录；目前原型没有真实审核数据，需确认数据来源。
6. **数据规模**：原型写 4.28PB / 1.8 亿条；真实首批数据规模、单批最大文件、是否允许抽样外推？
7. **语料授权与合规**：版权检测的哈希库、原创性 API、授权台账由谁提供？
8. **算子调用模式**：同步 `/predict` 还是异步任务？现有协议是同步，PB 级必须靠平台分片循环；是否新增异步 job 契约？
9. **报告责任**：HTML/PDF/Excel 是算子生成还是平台渲染？建议算子只产报告数据包，渲染归平台，避免算子承担排版。
10. **Comic 额外模块**：第 8 节列出的策略仿真/智能推荐/参考复刻/数据集包分析是否本次交付？
