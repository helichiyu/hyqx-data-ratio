## 1. 工程布局与构建上下文

**唯一 Docker 构建上下文 = `operator/` 目录。** 仓库根只保留文档、脚本、TODO 与业务仓库；算子运行期文件全部在 `operator/` 下。

```text
数据配比/
├── operator/                      # 唯一 Docker 构建上下文
│   ├── Dockerfile
│   ├── .dockerignore              # allowlist：排除 tests/dataset/output/README
│   ├── docker-compose.yml         # 单服务 op-data-mixing，端口 17025
│   ├── inference.py               # 唯一 HTTP 入口：五端点 + /health + 路由
│   ├── requirements.txt
│   ├── map.json                   # 22 条注册表（版本、语义编码、依赖）
│   ├── baseline/                  # 进镜像：tree-snapshot / source-map / thresholds / compliance（合规词表）
│   ├── weights/                   # 单一权重根（见第 10 节）
│   ├── _template/                 # 模板，不登记为算子、不进镜像
│   └── dm-<对象>-<动作>/          # 22 个算子包，目录名即包名
│       ├── __init__.py
│       ├── core.py                # core.run(input_path, params, seed, output_dir) -> dict
│       ├── configs/               # 阈值/标签映射/规则（进镜像）
│       ├── utils/                 # 解析/特征/评分/校验（进镜像）
│       ├── tests/                 # 仅仓库，不进镜像/压缩包
│       ├── dataset/               # 仅仓库
│       ├── output/                # 仅仓库
│       └── README.md              # 仅仓库
├── scripts/                       # 仓库工具，不进镜像
├── tests/                         # 根契约测试，不进镜像
├── docs/                          # 文档、Schema、样例、证据，不进镜像
└── todos/
```

约束：

1. 单镜像、单入口：22 个算子不各自实现 HTTP 层、不各自建 Dockerfile。
2. 包名 = 目录名 = `operatorId`（含连字符，如 `dm-multimodal-analysis`）。
3. 包内只用相对导入（`from .utils import ...`）；禁止 `import dm-x`（连字符不是合法标识符）。
4. `inference.py` 用 `importlib.util.spec_from_file_location` 按路径注册包名，再用 `importlib.import_module("<operatorId>.core")` 加载。
5. `core.py` 不得依赖 FastAPI/HTTP；算子间禁止 import、禁止共享运行期状态。
6. `baseline/`、`weights/` 是唯一共享数据/权重入口，进镜像；`docs/`、`scripts/`、`tests/`、`todos/` 不进镜像。

## 2. 五端点协议

所有路径前缀为 `/{operatorId}`。平台算子池地址按 `http://<host>:17025` 配置。

| 端点 | 方法 | 作用 | 关键约束 |
| --- | --- | --- | --- |
| `/{operatorId}/healthz` | GET | 探针 | 不鉴权；返回 `ready/device/deviceRequested/cudaAvailable/weightsOk/dependencyStatus`；`device` 为实际设备，`ready` 不代表权重就位 |
| `/{operatorId}/uploadFile` | POST | 上传输入 | `multipart/form-data`；字段 `file`；可选 `uniqueId`（query 或 form）；落盘 `INPUT_DIR/<uniqueId>/` |
| `/{operatorId}/predict` | POST | 执行计算 | JSON 或 multipart；`inputFile` / `uniqueId` / `file` 三选一；可带 `params`、`seed` |
| `/{operatorId}/downloadFile` | GET | 下载产物 | `?path=<绝对路径>`；文件返回字节流，目录打 zip；二进制响应不套信封 |
| `/{operatorId}/removeFile` | POST | 清理 | JSON `{path}` 或 `{uniqueId}`；幂等；拒绝输入/输出根目录与越界路径 |

另有平台兼容探针：

- `GET /health`、`GET /healthz`：聚合状态，返回 `status/operatorCount/readyCount`，供平台探针使用（Q-10）。算子不重复实现两套探针。

### 2.1 uploadFile

请求：

```text
POST /{operatorId}/uploadFile?uniqueId=<optional>
Content-Type: multipart/form-data
file=<binary>            # 必填
uniqueId=<string>        # 可选；缺省时按文件内容 sha256 生成 up_<16 hex>
```

响应（成功）：

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "operatorId": "dm-multimodal-analysis",
    "uniqueId": "batch-001",
    "directory": "/data/input/batch-001",
    "files": ["a.txt", "b.pdf"],
    "filePaths": ["/data/input/batch-001/a.txt", "/data/input/batch-001/b.pdf"],
    "skipped": ["c.exe"]
  }
}
```

规则：

- `uniqueId` 正则：`^[A-Za-z0-9][A-Za-z0-9._-]{0,127}$`；已存在同名目录时整体覆盖（幂等）。
- 单文件后缀必须在收件白名单内：文本/JSON/XML/PDF/图像/音频/视频/Parquet。
- `.zip` 先解压：只取 basename（防 zip-slip）、白名单过滤、重名保留第一个、限制成员数与解压总量；符号链接成员跳过。
- 缺省 `uniqueId` 由内容哈希生成，同内容重复上传落到同一目录。

### 2.2 predict

JSON 请求：

```json
{
  "uniqueId": "batch-001",
  "params": {"k": 1},
  "seed": 42
}
```

或 `inputFile` 传容器内绝对路径；multipart 时字段为 `file`、`uniqueId`、`params`（JSON 字符串）、`seed`。

- `inputFile`、`uniqueId`、multipart `file` 三选一；同时提供多个返回 `400 INVALID_REQUEST`。
- `params` 必须是 JSON 对象；`seed` 必须是整数；缺省 seed 取 `DEFAULT_SEED`（默认 42）并写回结果。
- `.zip` 输入会解压到 `OUTPUT_DIR/<operatorId>/<runId>/_input/extracted/` 后传给 `core.run`。
- 成功响应 `data` 见第 4 节；业务失败 `code=1`（如 `OPERATOR_NOT_IMPLEMENTED`）仍返回 HTTP 200。

### 2.3 downloadFile

- `path` 必须是 `INPUT_DIR` 或 `OUTPUT_DIR` 下的绝对路径。
- 文件：`FileResponse` 原始字节，`Content-Disposition` 带文件名。
- 目录：服务端打 zip（只打包普通文件、不跟随符号链接），下载完成后删除临时 zip。
- 不存在返回 `404 INPUT_NOT_FOUND`；越界/格式错误返回 `400`。

### 2.4 removeFile

- `{"path": "..."}` 或 `{"uniqueId": "..."}` 二选一。
- 幂等：目标不存在时仍返回 `code=0`，`data.removed=false`。
- 拒绝：输入/输出根目录本身（`ROOT_PATH_FORBIDDEN`）、符号链接（`PATH_SYMLINK`）、越界路径。

### 2.5 healthz

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "ready": true,
    "operatorId": "dm-multimodal-analysis",
    "semanticCode": "corpus_ingest_multimodal_parse_v1",
    "version": "0.1.0",
    "device": "cpu",
    "deviceRequested": "auto",
    "cudaAvailable": false,
    "weightsOk": false,
    "dependencyStatus": {"core": "ok", "ffmpeg": "ok", "weights": "missing"},
    "inputDir": "/app/runtime/transport/input",
    "outputDir": "/app/runtime/transport/output"
  }
}
```

定义：

- `ready = core 可导入 AND INPUT_DIR/OUTPUT_DIR 可写 AND 路由已注册`；**不包含权重**。
- `device` 是实际设备（`cpu` 或 `cuda:N`），以 `torch.cuda.is_available()` 为准；`deviceRequested` 是 `DEVICE` 环境变量（默认 `auto`），`cudaAvailable` 表示 CUDA 是否可用；请求 GPU 但不可用时 `device` 回落 `cpu`，并附 `deviceFallbackReason`。GPU 可用时另返回 `gpuName`、`cudaRuntime`、`torchVersion`。
- `weightsOk` 单独表达：`requiresWeights=false` 为 `true`；为 `true` 时检查 `weights/shared/` 或 `weights/<operatorId>/` 是否有权重文件。
- `dependencyStatus`：`core`/`ffmpeg`/`weights` 三项状态，便于平台定位。
- core 导入失败时 `ready=false`、`dependencyStatus.core=import_failed`、附 `importError`；HTTP 仍为 200。

## 3. 统一信封与 HTTP 状态码

信封：

```json
{"code": 0, "msg": "success", "data": {}}
```

| 场景 | HTTP | code | 说明 |
| --- | --- | --- | --- |
| 成功 | 200 | 0 | 允许部分样本失败，失败数在 `data.failedCount` |
| 业务失败 | 200 | 1 | 如无语音、标签树不匹配、`OPERATOR_NOT_IMPLEMENTED`；必须带 `data.reasonCode` |
| 参数/路径格式错误 | 400 | 1 | `INVALID_REQUEST` / `INVALID_JSON` / `PATH_INVALID` / `PATH_OUT_OF_BOUNDS` / `UNIQUE_ID_INVALID` / `UNSUPPORTED_FILE_TYPE` |
| 资源不存在 | 404 | 1 | `INPUT_NOT_FOUND` / `NOT_FOUND` |
| 方法不允许 | 405 | 1 | `METHOD_NOT_ALLOWED` |
| 超过大小限制 | 413 | 1 | `UPLOAD_TOO_LARGE` / `ZIP_TOO_LARGE` |
| 模型/依赖不可用 | 503 | 1 | `CORE_IMPORT_FAILED` / `DEPENDENCY_UNAVAILABLE` |
| 内部错误 | 500 | 1 | `INTERNAL_ERROR` / `CONTRACT_VIOLATION` |

所有失败响应统一为 `{"code":1,"msg":"中文原因","data":{"reasonCode":"..."} }`，不允许只返回 `false`。未知路由与参数校验失败也套信封（`NOT_FOUND` / `INVALID_REQUEST`）。

### 3.1 reasonCode 表

| reasonCode | HTTP | 含义 |
| --- | --- | --- |
| `INVALID_REQUEST` | 400 | 参数缺失/类型错误/多输入冲突 |
| `INVALID_JSON` | 400 | 请求体不是合法 JSON 对象 |
| `INPUT_REQUIRED` | 400 | 未提供 inputFile/uniqueId/file |
| `INPUT_NOT_FOUND` | 404 | 输入路径或 uniqueId 不存在 |
| `PATH_INVALID` | 400 | 非绝对路径、`file://`、`~`、控制字符 |
| `PATH_OUT_OF_BOUNDS` | 400 | 解析后落在 INPUT_DIR/OUTPUT_DIR 之外 |
| `PATH_SYMLINK` | 400 | 路径包含符号链接 |
| `ROOT_PATH_FORBIDDEN` | 400 | 操作输入/输出根目录本身 |
| `UNIQUE_ID_INVALID` | 400 | uniqueId 不合规 |
| `UNSUPPORTED_FILE_TYPE` | 400 | 后缀不在收件白名单 |
| `UPLOAD_TOO_LARGE` | 413 | 单次上传超限 |
| `ZIP_INVALID` | 400 | 不是有效 zip / zip 内无白名单文件（predict 阶段） |
| `ZIP_EMPTY` | 400 | zip 内没有白名单允许的文件（upload 阶段） |
| `ZIP_TOO_LARGE` | 413 | zip 解压总量超限 |
| `AUTH_REQUIRED` | 401 | 启用 `REQUIRE_X_TOKEN=true` 时缺少 X-Token |
| `CORE_IMPORT_FAILED` | 503 | 算子核心不可导入 |
| `DEPENDENCY_UNAVAILABLE` | 503 | 模型/权重/外部依赖不可用 |
| `OPERATOR_NOT_IMPLEMENTED` | 200 | S0 骨架未实现（业务失败） |
| `CONTRACT_VIOLATION` | 500 | `core.run` 返回值不是 dict |
| `NOT_FOUND` | 404 | 路由不存在 |
| `METHOD_NOT_ALLOWED` | 405 | HTTP 方法不允许 |
| `INTERNAL_ERROR` | 500 | 未预期异常（附 `error.log`） |

## 4. 结果契约（predict 的 data）

```json
{
  "operatorId": "dm-multimodal-analysis",
  "semanticCode": "corpus_ingest_multimodal_parse_v1",
  "operatorVersion": "0.1.0",
  "modelVersion": null,
  "treeVersion": "taxonomy-1013-pending",
  "paramsHash": "sha256:...",
  "seed": 42,
  "runId": "96bffb3fd5933b9a",
  "inputFingerprint": "sha256:...",
  "sampleCount": 10000,
  "successCount": 9980,
  "failedCount": 20,
  "failedSamples": [{"id": "...", "reasonCode": "DECODE_FAILED"}],
  "metrics": {},
  "artifacts": [{"type": "parquet", "path": "...", "sha256": "..."}],
  "outputFilePath": "/abs/path/result.jsonl",
  "outputDir": "/abs/path/",
  "cached": false
}
```

规则：

- `core.run` 必须返回 dict，可只填业务字段；协议字段（`operatorId/semanticCode/operatorVersion/paramsHash/seed/runId/inputFingerprint/outputDir`）由 HTTP 层兜底，算子不得改写。
- 文件型算子必须写 `result.jsonl`（逐条一行），`outputFilePath` 指向它；规则类算子可把结果放 `data.result`。
- `modelVersion`/`treeVersion` 无对应模型/树时为 `null`，不得编造。
- 失败样本必须带 `id` + `reasonCode`，并计入 `failedCount`；禁止静默丢弃。
- 完整结构以 `docs/算子开发/schemas/result.schema.json` 为准。

## 6. 路径安全

必须实现（对应 `tests/test_path_gate.py`）：

1. 只接受绝对路径；`resolve(strict=False)` 后必须落在 `INPUT_DIR` 或 `OUTPUT_DIR` 内。
2. 拒绝 `file://`、`~`、控制字符、相对路径、`..` 越界。
3. 逐段检查符号链接；目标本身是符号链接时拒绝访问/删除。
4. zip 解压只取 basename，防 zip-slip；白名单后缀；限制成员数与解压总量；跳过符号链接成员。
5. `removeFile` 拒绝输入/输出根目录本身。
6. 下载目录只打包普通文件，不跟随符号链接。

## 8. 幂等与可复现

```text
paramsHash     = sha256(canonical_json(params))
inputFingerprint = sha256(文件内容 | 目录相对路径+大小+内容哈希)
runId          = sha256(inputFingerprint + operatorVersion + paramsHash + seed)[:16]
runDir         = OUTPUT_DIR/<operatorId>/<runId>
```

- 同一输入、版本、参数、seed 必须落到同一 `runDir`；第二次调用读取 `result.json` 返回缓存结果（`data.cached=true`），不产生第二份产物。
- 失败不写 `result.json`；重跑覆盖同一目录并留 `error.log`。
- 输入目录含符号链接时拒绝计算。
- `runId` 与 `inputFingerprint` 写入结果，便于复算。
