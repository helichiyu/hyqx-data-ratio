## 0. 这份任务书怎么用

1. **本任务书不排日历时间。** 阶段按依赖顺序推进，P0 最小链路先冻结，P1 能力在依赖满足后并行补齐；每个阶段以「门禁」而不是「日期」收口。
2. **一个算子 = 一个工作包。** 大型算子拆成模态子包或步骤子包（如 `OP-01-T/I/A/V`、`OP-05-T/I/A/V`），子包共享同一算子服务、同一版本号。
3. **AI 执行者**按阶段顺序领取任务卡，开工前读第 2.5 节上下文包，完成后按第 2.6 节提交回执与证据。
4. **人工评审者**按第 5 节阶段门禁与第 7 节验收标准逐项核对；只认可复算的证据，不认「已实现」「测试通过」的口头结论。
5. **任务卡中的「必须」是验收项；「建议」是实现参考。** 不得为了省事删减必须项；确需偏离时，在回执中写明理由、影响与替代验证方式，交人工确认。
6. **本任务书与 xlsx 冲突时以 xlsx 的算子范围、优先级为准；与 FGW 原文冲突时以 FGW 为准。** 发现冲突先登记，不自行改口径。

## 1. 目标与范围

### 1.1 总目标

把交互原型中 90% 以上的常量、哈希和 `Math.random()` 结果替换为**对真实语料可核验、可复算的计算或推理**，交付 22 个可独立部署、独立验收、独立上架的算子服务，并打通以下最小真实链路：

```text
批次接入
  → OP-01 多模态识别与解析
  → OP-02 标准化、元数据与去重
  → OP-03 句向量与主题聚类
  → OP-05 多模态自动打标（文本/图像/音频/视频）
  → OP-08/09/10/14 语料画像
  → OP-15 配比引擎
  → OP-17 数据组装与打包
  → OP-18 数据评测
  → OP-19 配比分析与报告
```

P1 算子（OP-04/06/07/11/12/13/16/20/21/22）在 P0 链路稳定后并行补齐，最终并入全量验收。

### 1.3 明确不在范围

以下能力属于平台、前端或人工，不得在算子中实现，也不得作为算子验收内容：

- 分类体系树、领域树、能力树的增删改、启停、排序、收藏；
- 场景、配方包、任务、风险工单、专家校验任务的 CRUD 与状态机；
- 列表筛选、分页、弹窗、滑块、进度条、通知、权限、审计日志；
- 人工审核、人工归类、专家签署、风险处置；
- 对象存储写入、数据库落库、报告下载入口、图表渲染；
- Neo4j、FAISS、ES/ClickHouse 的部署、容量与健康度面板；
- 源库增量拉取（原 ING-09），归平台连接器。

判定原则：**算子必须对真实语料产生可核验的新结果；只能搬运或展示平台已有数据的，不是算子。**

### 1.4 完成定义（总）

本项目「完成」不是 22 个目录都有代码，而是同时满足：

1. 22 个算子均通过单算子 DoD（第 7.1 节），状态为「已验收」；
2. P0 最小链路在真实批次上端到端跑通，产物可下载、可复算、可追溯；
3. 全量链路（含 P1）在真实批次上跑通，报告数据包与评测结果齐全；
4. 所有指标、标签、阈值、模型、树均有版本与口径说明，无常量/随机数伪造；
5. 平台侧按统一协议完成联调：X-Token、10 MiB 请求限制、超时、幂等重跑、断点续跑；
6. 审计追溯矩阵（FGW 12.x/13.x → 算子 → 证据路径）填写完整。

## 2. 开发模式：AI 工作包

### 2.1 工作包定义

| 项 | 规则 |
| --- | --- |
| 粒度 | 默认一个算子一个工作包；大型算子可拆子包，但共享同一服务与版本号 |
| 自包含 | 每个算子目录独立可构建、可启动、可测试、可打包；禁止跨算子 `import` |
| 代码复用 | 允许复制小型工具函数，但必须在文件头注明来源与版本；公共契约只以文档/JSON Schema 形式共享，不做代码依赖 |
| 子包拆分 | `OP-01-T/I/A/V`、`OP-02-A/B/C`、`OP-05-T/I/A/V`、`OP-08-A/B/C`、`OP-14-A/B` 可并行；合并时统一版本与结果信封 |
| 交付根 | `operator/<目录名>/`；模板由 S0 创建于 `operator/_template/`，`_template` 不登记为算子 |

### 2.2 人机分工

| 事项 | AI 执行者 | 人工评审者 |
| --- | --- | --- |
| 读文档、拆任务、写代码、写测试 | 负责 | 抽查 |
| 运行样例、产出证据、填指标 | 负责 | 复核 |
| 业务口径、阈值、权重、树版本 | 只提建议，不擅自定稿 | **负责确认** |
| 真实数据、人工标注、专家结果 | 只消费，不伪造 | **负责提供/授权** |
| 模型、权重、许可证、算力 | 只选型与验证 | **负责审批** |
| 阶段门禁、验收签字 | 提交材料 | **负责判定** |
| 平台接口、部署、令牌 | 按契约实现 | **负责联调** |

### 2.3 工作包执行流程

```text
1. 读上下文包（2.5）→ 输出「开工检查」：依赖是否齐、数据是否可读、模型是否可用、环境是否满足
2. 做一个最小真实切片：每模态/每分支先跑通 1 条真实样本，端到端出结果
3. 补齐主流程：按任务卡的输入/输出/实现要点实现，不提前优化
4. 加测试：纯函数单测 → 服务契约测试 → 真实样本回归
5. 跑样例批次：记录命令、环境、结果、失败原因、耗时/内存
6. 写 README / metrics / 证据索引：指标未评测就写 null 并说明原因，不编造
7. 提交工作包回执（2.6）→ 等待阶段门禁评审
```

**停止条件（遇到即停，登记 BLOCKED，不硬编造）：**

- 真实数据或标注未到位；
- 模型/权重不可获得、许可证未确认；
- 依赖算子的输出契约未冻结；
- 业务阈值/口径未确认且会影响结论；
- 平台服务（Neo4j/FAISS/对象存储）不可用且无法本地替代验证；
- 任何需要「假装成功」才能继续的环节。

### 2.4 AI 硬性纪律

1. **禁止伪造结果**：不得用 `random`、哈希、常量数组、写死分数、`sleep` 模拟进度来充当计算结果。
2. **禁止把 mock 当验收**：`FakeEngine`、样例桩、空实现只能用于单测；验收证据必须来自真实模型/真实样本。
3. **禁止口头完成**：没有命令输出、结果文件、指标文件、证据路径的「已完成」一律无效。
4. **禁止改契约不登记**：共享契约、结果信封、错误码、目录结构变更必须升版本并经人工确认。
5. **禁止跨算子耦合**：不得从其他算子目录 import 代码；不得共享运行期状态；不得依赖其他算子的容器路径。
6. **禁止提交敏感物**：模型权重、原始语料、密钥、Token、个人数据不得进 git；样例数据必须可公开或已授权。
7. **禁止编造指标**：没有人工标注/真值时不填准确率、F1、Kappa；写 `null` + `blockedReason`。
8. **禁止改历史结果**：已验收的 changeSet/结果/证据不得回溯修改；修正靠新版本。
9. **禁止全量入内存**：语料处理必须流式/分片；单请求不内联语料；大文件走 `uploadFile` + 分片。
10. **禁止魔法值**：阈值、权重、字典、路径必须来自配置或基线文件，并记录来源与版本。
11. **禁止跳过失败**：失败样本必须记录 `reasonCode` 与计数，不得静默丢弃。
12. **禁止越权决策**：模型许可证、数据授权、业务阈值、树版本由人工确认，AI 只给建议与证据。

## 3. 统一工程契约（S0 冻结，所有算子遵守）

### 3.1 算子目录结构

```text
operator/dm-<对象>-<动作>/
├── Dockerfile                     # 镜像构建；权重构建期校验
├── inference.py                   # HTTP 服务入口（唯一对外入口）
├── requirements.txt               # 锁定版本
├── map.json                       # 算子 ID、语义编码、tag、版本、模态
├── weight/                        # 模型权重（不进 git）；SHA256SUMS 进 git
├── <package>/                     # 与目录名一致的 Python 包
│   ├── __init__.py
│   ├── core.py                    # 纯计算/推理核心，可脱离 HTTP 调用
│   ├── configs/                   # 阈值、标签映射、规则
│   ├── utils/                     # 解析、特征、评分、校验
│   ├── dataset/
│   │   ├── sample/                # 可运行小样例（进 git）
│   │   └── DATA_SCHEMA.md         # 输入数据格式说明
│   ├── output/
│   │   ├── model/metrics.json     # 指标；未评测字段为 null
│   │   └── evidence/<runId>/      # 运行证据（结果小文件/报告可进 git，大产物不进）
│   └── README.md                  # 用途、边界、接口、方案、启动、测试、指标
└── tests/                         # 单测 + 契约测试 + 真实样本回归
```

约束：

- 目录名、包名、`operatorId` 三者一致；`operatorId` 发布后不可改。
- `core.py` 不得依赖 FastAPI/HTTP；HTTP 层只做收参、路径校验、调用 core、封装信封。
- `configs/` 中每个阈值必须写明来源（业务确认/论文/联调初值）与版本。
- `dataset/sample/` 只放可公开或已授权的小样本；不得放生产语料。
- 大产物（Parquet、成品包、索引）写 `OUTPUT_DIR` 或对象存储，不写仓库。

### 3.2 服务协议

所有算子统一实现以下端点（`{operatorId}` 即目录名）：

| 端点 | 方法 | 作用 | 说明 |
| --- | --- | --- | --- |
| `/{operatorId}/healthz` | GET | 探针 | 返回 `ready/device/weightsOk/dependencyStatus`；不要求鉴权 |
| `/{operatorId}/uploadFile` | POST | 上传输入 | `multipart/form-data`；字段 `file`；可选 `uniqueId`；落盘到 `INPUT_DIR/<uniqueId>/` |
| `/{operatorId}/predict` | POST | 执行计算 | JSON 或 multipart；传 `inputFile`（容器内绝对路径）或 `uniqueId`；可带 `params`、`seed` |
| `/{operatorId}/downloadFile` | GET | 下载产物 | 文件返回字节流，目录打 zip；二进制响应不套信封 |
| `/{operatorId}/removeFile` | POST | 清理 | JSON `{path}` 或 `{uniqueId}`；幂等；拒绝根目录与越界路径 |

统一信封：

```json
{
  "code": 0,
  "msg": "success",
  "data": {}
}
```

- `code=0`：成功（允许部分样本失败，失败数在 `data.failedCount`）。
- `code=1`：业务失败（如无语音、标签树不匹配），HTTP 200。
- HTTP 400：参数/路径格式错误；404：输入不存在；413：超过大小限制；503：模型/依赖不可用；500：内部错误。
- 所有业务失败必须带 `reasonCode` 与中文 `msg`；不得只返回 `false`。

平台兼容：

- 平台若调用 `GET /health` 而非 `/{operatorId}/healthz`，由 S0 在网关/探针层适配；算子不重复实现两套探针。
- 平台单请求上限 10 MiB：**语料绝不内联 JSON**，必须 `uploadFile` 后传路径/对象存储 ID；大文件由平台分片多次调用。
- 超时建议：解析/ASR/视频类 20–30 分钟；规则/配比类 5–30 秒；长任务必须支持幂等重跑与断点续跑。
- 鉴权：平台统一 `X-Token`；算子只校验存在性与透传，不自行实现账号体系。

路径安全（必须实现）：

- 只接受绝对路径；解析后必须落在 `INPUT_DIR` 或 `OUTPUT_DIR` 内；
- 拒绝 `file://`、`~`、控制字符、符号链接、`..` 越界；
- zip 解压必须防 zip-slip，只取 basename，白名单扩展名，限制解压总量；
- `removeFile` 拒绝输入/输出根目录本身。

### 3.3 数据契约

标准记录（文本类；图像/音频/视频以 `metadata` 承载模态属性）：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `record_id` | string | 是 | 稳定唯一 ID；由输入指纹/平台 ID 生成，禁止自增 |
| `modal` | string | 是 | `text` / `image` / `audio` / `video` |
| `source` | string | 是 | 六类来源 alias（`web_text`/`books`/`code`/`science`/`wiki`/`dialogue`），可附原始来源 |
| `text` | string | 否 | 正文/转写/OCR；无文本为 null |
| `metadata` | object | 是 | 格式、大小、哈希、分辨率/采样率/时长/帧率、拍摄时间等 |
| `quality` | object | 是 | 解析/解码/完整率/异常标记 |
| `labels` | array | 否 | 打标结果：`path`、`confidence`、`topK`、`evidence`、`modelVersion`、`treeVersion` |
| `partitions` | object | 是 | `modal`、`source`、`dt` |
| `hashes` | object | 是 | `md5`、`sha256`、`simhash`（适用时） |

标准产物：

- 文本/元数据：Parquet，zstd，row group 约 128 MB；按 `modal/source/dt` 分区。
- 图像：WebP + phash；保留原始尺寸/色彩空间/EXIF 摘要。
- 音频：16 kHz mono WAV + 梅尔谱（按需）；保留原始采样率/声道/码率。
- 视频：H.264 标准转码 + 关键帧 + 帧-时间戳表；音轨转音频链路。
- manifest：JSON/JSONL，必含输入指纹、算子版本、参数哈希、条数、成功/失败、输入/输出字节、压缩比、seed、模型/树版本、产物 SHA-256。

### 3.5 幂等与可复现

- **输出路径确定**：`runId = sha256(inputFingerprint + operatorVersion + paramsHash + seed)[:16]`；同一输入、版本、参数、seed 必须落到同一路径，重跑覆盖或断点续跑，不产生第二份结果。
- **固定 seed**：聚类、抽样、选样、评测抽样必须显式接收 `seed`；未传时使用配置默认值并写回结果。
- **推理确定性**：模型推理关闭 dropout、固定 batch/精度策略、温度 0（适用时）；无法完全确定时，记录 `deterministic=false` 与原因。
- **版本四件套**：`operatorVersion`、`modelVersion`、`treeVersion`、`paramsHash` 必须出现在结果、manifest、metrics 与 README。
- **可复算**：任意结果可由「输入指纹 + 算子版本 + 参数 + seed」复算；README 给出复算命令。

### 3.6 模型、权重与镜像

- 模型选型自由，但必须满足两条底线（参考敏感成分分析开发约定）：
  1. **业务标签映射固定**：模型输出必须映射到本任务书的标签/字典口径，不得直接暴露模型私有标签；
  2. **先验证后锁定**：开工先用真实样本验证自选模型；指标明显低于开源基线时回退到任务卡推荐模型，并记录回退原因。
- 权重不进 git；`weight/SHA256SUMS` 进 git；Dockerfile 构建期校验文件大小与 SHA-256。
- 服务器无外网：权重必须打进镜像或挂载离线目录；运行期不得联网下载。
- 许可证：记录模型/权重/数据许可证；许可证不明或冲突时登记 BLOCKED，交人工审批。
- GPU/CPU：`healthz` 返回 `device`；无 GPU 时按任务卡回退策略运行，不得假装 GPU。

### 3.7 测试与证据

| 层级 | 要求 | 是否可作为验收证据 |
| --- | --- | --- |
| 纯函数单测 | 评分、归一化、分段、映射、校验、抽样公式 | 否（只证明逻辑） |
| 服务契约测试 | 五端点、信封、路径闸门、错误码、幂等、zip-slip | 是（协议验收） |

| 性能/资源 | 吞吐、延迟、内存峰值、并发 | 是（工程验收） |

## 7. 验收与证据链

### 7.1 单算子 DoD（Definition of Done）

一个算子只有同时满足以下 12 条，才能标记「已验收」：

- [ ] 1. 代码可构建、服务可启动，`healthz` 返回 ready；
- [ ] 2. 五端点（healthz / uploadFile / predict / downloadFile / removeFile）契约测试通过，含路径越界、zip-slip、超大文件、幂等重跑；
- [ ] 3. 纯函数单测覆盖核心公式/映射/边界；FakeEngine 测试与真实模型测试分离；
- [ ] 4. 真实样本回归达到任务卡指定量，结果文件与失败清单齐全；
- [ ] 5. 输出符合第 3.3/3.4 节 Schema，路径/版本/seed/哈希字段完整；
- [ ] 6. 结果可复算：同输入、版本、参数、seed 重跑一致（或记录 `deterministic=false` 原因）；
- [ ] 7. `metrics.json` 有真实指标；无真值时字段为 `null` + `blockedReason`，不编造；
- [ ] 8. `README.md` 包含用途、边界、接口、技术方案、启动命令、测试命令、指标口径、已知限制；
- [ ] 9. `dataset/sample/` 有可运行样例与 `DATA_SCHEMA.md`；
- [ ] 10. 证据目录完整：命令、环境、输入 manifest、结果、指标、失败、产物哈希、日志；
- [ ] 11. 代码审查通过：无 `random`/常量伪造、无跨算子 import、无密钥/权重/生产语料；
- [ ] 12. `registry.json` 状态更新为「已验收」，证据路径可访问。

### 7.2 阶段 DoD

- [ ] 阶段内所有 P0 算子达到单算子 DoD；P1 算子按阶段增强门禁判定；
- [ ] 阶段集成测试在共享真实批次上跑通，上游产物被下游真实消费；
- [ ] 跨算子版本一致：同一阶段使用同一 `treeVersion`，打标/评测使用同一 `modelVersion`；
- [ ] 阶段证据索引生成，人工门禁逐项签字；
- [ ] 遗留问题分为「不阻塞验收」与「阻塞项」；阻塞项写明责任方与解除条件。

### 7.3 全链路 DoD

- [ ] S7-A/S7-B 链路真实跑通，无手工中间结果；
- [ ] 所有产物有 manifest、哈希、版本、seed；
- [ ] FGW 12.x/13.x 追溯矩阵每行有算子与证据路径；
- [ ] 平台联调通过（X-Token、10 MiB、超时、幂等、断点）；
- [ ] 审计可复算：任意结果可由命令 + 输入 + 版本复现；
- [ ] 无原型假数据残留（代码审查与 `git grep` 记录）。

## 9. 变更与状态管理

### 9.1 状态机

```text
未开始 → 进行中 → 自测通过 → 待评审 → 已验收
                    │           │
                    └─ 阻塞 ←───┘
```

- 「自测通过」必须有完整证据目录；
- 「待评审」必须提交工作包回执；
- 「已验收」必须由人工门禁确认；
- 「阻塞」必须写明原因与解除条件，不得长期静默。

### 9.2 契约变更

- 目录、端点、信封、错误码、数据 Schema 属于共享契约；
- 变更必须：升版本 → 更新 `算子工程契约.md` → 通知所有受影响算子 → 回归契约测试 → 人工确认；
- 已验收算子的结果字段只增不改；删除/改类型按破坏性变更处理。

### 9.3 汇报机制（按事件触发，不按日历）

| 触发 | 输出 |
| --- | --- |
| 工作包完成/阻塞 | 工作包回执（2.6） |
| 阶段门禁前 | 阶段报告：算子状态表、证据索引、风险、待确认项 |
| 契约变更 | 变更说明：影响范围、版本、回归结果 |
| 全链路验收 | 验收报告 + FGW 追溯矩阵 + 证据总索引 |
