#### 关键粒度判断（已确认）
**12.1-1 数据源识别的颗粒度：样本级为主，数据集级为辅。**

+ **样本级（主）**：配比算的是"样本占比"，必须逐条样本判断来源类别才能统计出占比；且一个数据集往往混合多源，数据集级只能贴"主导来源"粗标签。此标签与 12.2 打标体系同源，天然样本级。
+ **数据集级（辅）**：仍需要"主导来源 + 来源可信度"，用于聚合统计、来源归属管理——但那归 C6(基础信息分析)/C9(来源可信度) 用，不直接参与配比计算。
+ 审计落位：样本级数据源标签→支撑配比方案(12.1)；数据集级主导来源/可信度→支撑来源与覆盖分析(13.2/C6)。

#### 承接与落地
+ L1：C3 数据配比引擎 ｜ L3：F1 数据配比引擎
+ 产出物：数据源归类表、数据源×能力映射库、配比方案A/B、方案对比报告

### 12.2 构建包含数千种类型的详细数据类型体系
**归属**：L1 能力域 **C1（类型体系）+ C2（多模态打标）** —— 全文档最重一节  
**原文要点**：四模态（文本/图像/音频/视频）类型体系树，"模态-一级-二级-细分"标签精准归类，覆盖数千种类型；为每条多模态数据分配细分类型标签，人工审核+自动化工具结合打标。

**架构口径（已确认）**

+ **模态为根**：类型体系以模态（文/图/音/视）为根，层级 `模态-一级类别-二级类别-细分类型`，覆盖数千种。
+ **标签深度可变**：4段/5段均可，以"唯一无歧义落到细分"为准（例：`文本-通用文本-新闻资讯-时政新闻`4段 vs `...-财经新闻-股市`5段）。
+ **数据源是独立"来源标签"，不进类型树**：12.1 数据源（6类）是独立来源 tag，树的根保持模态；二者是两套标签，靠映射表关联，**不合并**。
+ **粒度**：样本级打标为主，数据集级用于聚合统计。
+ 与 12.1 关系：数据源=粗维度（来源视角，喂配比A/B）、12.2=细维度（内容视角，喂12.3细分配比），同一批样本的多维标签。

**「数千种」乘法账（审计自证）**：`四模态 × Σ(每模态一级×二级×细分类型数)` ≈ **3000+ 种**；有效依据是类型树导出清单的实际节点数，可逐一核验。

#### 输入规格（已确认）
12.3 的引擎输入分两类，切勿混淆：

| 输入 | 类型 | 谁设/谁出 | 特征 |
| --- | --- | --- | --- |
| 模型定位（通用/专业） | 参数 | 业务侧配置 | 一次配比一个值，运行时不变 |
| 应用场景（对话/检索/创作） | 参数 | 业务侧配置 | 可多选，决定标签侧重 |
| 训练阶段（预训练/微调） | 参数 | 业务侧配置 | 决定标签粒度（预训练到四级/微调到二级） |
| 样本级标签 | 数据集（已分析产物） | 12.2 打标引擎产出 | 带标签体系列结构，静态分析结果 |


> 一句话：**参数（定位/场景/阶段）= 配比引擎的"旋钮"；样本级标签 = 配比引擎的"食材缓冲区"。** 参数决定"按什么逻辑配"，标签数据集决定"能按哪些标签去分"，引擎拿参数扫描标签数据集算出占比。
>

#### 配比源头输入规格深化（2026-10-08 补充）
**A. 配比源头真正要"业务用户输入"的是什么**  
配比进程的源头输入 = 一组**业务决策参数（旋钮）**，不是语料数据：

| 输入项 | 类型 | 例子 | 谁输 |
| --- | --- | --- | --- |
| 模型定位 | 单选 | 通用 / 专业（能源） | 业务配置 |
| 应用场景 | 多选 | 对话 / 检索 / 创作 | 业务配置 |
| 训练阶段 | 单选 | 预训练 / 微调 | 业务配置 |
| 高频核心标签集 | 圈选 | 类型树上勾选 {行业问答,设备诊断} | 业务圈选 |
| 30% 下限阈值 | 数值 | 30% | 后台配置 |
| 通用/专业权重滑杆(12.4) | 滑杆 | 专业70% | 业务调整 |
| 偏见降权指令(12.4) | 指令 | 降某问题源权重 | 业务调整 |


+ **业务用户输入 = 决策参数**（回答"模型要成为什么、按什么逻辑喂"）；**语料/标签是上游 12.1/12.2 已产出的"食材"，配比源头不要求用户重新给数据**。呼应第9条：输入是"需求决策(要什么)"，系统自动完成"方案计算(怎么喂)"。

**B. 模型定位 vs 训练阶段：不重复，是正交维度（易混点）**

|  | 模型定位 | 训练阶段 |
| --- | --- | --- |
| 回答 | 模型最终**是什么**（通用/行业） | 训练过程**哪个环节**（预训练/微调） |
| 决定 | 能力强项**方向** | 喂料**粗细/侧重** |
| 时间 | 终态/目标 | 过程/阶段 |


> 交叉关系：定位相同、阶段不同，配比完全不同——预训练(重广度/粗粒度宽覆盖) vs 微调(重专业/细粒度聚焦)。发改委并列写不是冗余，是两个正交配比维度。打个比方：**定位=定"往哪走"（方向），阶段=定"走到第几步"（环节）**。
>

**C. 高频核心标签集默认值机制：定位联动预置，非全集默认**

+ **可以给默认值**，且按**定位**联动：行业垂直→默认{行业问答,设备诊断,安全规程}；通用基座→默认{通用对话,常识,多语言}
+ **场景(多选)** → 默认集随场景动态增删（对话→加问答/指令；检索→加事实语料）
+ **阶段(会切换)** → 默认集重心变：预训练(宽/通用为主) vs 微调(窄/专业为主)
+ ⚠️ **边界**：默认值只能"预填"省手圈，**不能替代业务判断**——"哪个场景客户最不能容忍掉链子"是业务决策，系统猜不到，需人工确认收口。即"智能默认 + 人工兜底"。

**D. 配比发起实操（源头入口，用户实际做的四步）**

```plain
第1步 设旋钮：定位=专业 / 场景=对话 / 阶段=微调
第2步 圈场景：类型树上勾选核心标签（可用默认值预填）{行业问答,设备诊断,安全规程}
第3步 定权衡：专业70% 通用30%（12.4）
第4步 点"生成配比方案"
   └─ 系统自动：调用12.2已打标语料 + 前缀匹配捞核心样本 → 算占比 → 30%校验 → 出方案
```

#### 业务流案例（示例：能源行业专业大模型，微调阶段）
+ **输入**：1000 万条已打标语料（12.2 产出）+ 模型定位=专业 + 场景=对话 + 阶段=微调
+ **处理**：
    1. 三轴筛选配比对象（专业→行业语料加权；对话→加大问答标签；微调→粒度到二级类别）
    2. 算基准占比：通用对话32% / 能源行业问答40% / 代码技术8% / 学术论文6% / 长尾其他14%
    3. 覆盖度校验：确保一二级类别覆盖率100%，长尾（少数民族语言/甲骨文图像等）兜底不置零
    4. 动态迭代：识别"设备故障诊断问答"为薄弱标签，下轮从1%提到3%，记录调整日志
+ **输出**：细化配比方案 + 覆盖率报告 + 高频占比≥30%校验单 + 薄弱标签调整记录 → 下发 12.4
+ **审计链**：三轴细分→12.3-1✅ 高频≥30%→12.3-3✅ 覆盖100%→12.3-4✅ 迭代→12.3-5✅ 标签来源→12.2✅

### 12.4 调整通用数据与专业数据配比实现模型性能平衡
**归属**：L1 能力域 **C3（数据配比引擎）**，承接 12.3 输出  
**原文要点**：多样化配比（多元化→通用性好但深度浅）vs 窄范围配比（聚焦→深度高但通用性差）；数据配比是引入/减少社会偏见的途径；理想配比取决于模型预期应用（基座=>多样，行业=>聚焦）。

| --- | --- | --- | --- | --- |

| 12.4-2 | 偏见检测与治理 | 检测配比中数据源/群体偏见（单一文化/有害语言），支持调低高问题源权重 | 偏见检测报告 + 权重调整记录 | ②后台 |
| 12.4-3 | 数据源过滤策略 | 对已知问题内容的数据源实施过滤、降权 | 过滤规则 + 过滤后占比 | ②后台 |

#### 关系与判断
+ 12.4-1 是"通用/专业权重"的上层开关，12.3 三轴是标签级细化——先定大方向再细分，非重复。
+ 偏见治理（12.4-2/3）是审计加分项，原文明确"负责任 AI 的重要部分"，建议保留不砍。
+ 12.4-4 可做系统规则（③），基座→多样/行业→聚焦相对固定，写死最省。

#### 输入与输出（运算本质）
+ 输入：已打标语料（样本级标签）+ 参数三件套（定位/场景/阶段）+ 通用/专业滑杆 + 偏见降权指令
+ 输出：每条样本最终投喂占比 + 权衡对比图 + 偏见治理记录 + 影响评估报告

**核心运算公式（配比 = 加权占比）：**

```plain
有效条数(某样本) = 条数 × 权重
某类占比 = Σ(该类条数×权重) ÷ Σ(全部条数×权重)
投喂条数 = 总批次 × 占比
```

**条数 vs 权重（关键区分）：**

+ 条数 = 该类实际有多少样本（客观，做分母）
+ 权重 = 每条样本投喂时的"力气/份量"（人为设定，0~1 小数，乘在条数上）
+ 配比灵魂：条数是死的，权重是调节条数占比的旋钮（升权1.2/降权0.1/排除0）

#### 权重 = 采样频率 → 塑造模型参数（底层原理，已确认）
**权重本质是样本在多次训练中出现的频率，通过采样频率影响梯度，最终塑造模型参数：**

```plain
权重(每条的力气) → 采样频率(每轮出现次数/概率)
  → 梯度出现次数 = loss 中加权项大小
  → 参数更新被该样本反复拉动 (θ ← θ − η·Σwᵢ·(∂lossᵢ/∂θ))
  → 参数偏向高频样本 → 模型能力偏向它
```

+ 权重1.0=每轮正常1次；1.2=过采样1.2次；0.1=欠采样（约10轮见1次）；0=完全不见
+ 数学：`θ ← θ − η × Σᵢ wᵢ × (∂lossᵢ/∂θ)`，wᵢ 直接乘在每条样本的梯度项上
+ 等效说法：配比 = 过采样/欠采样（over/under-sampling）
+ **一句话：权重高=高频出现=多学；权重低=低频=少学；权重0=不见=不学。模型参数最终被"出现频率高"的样本塑造。**

#### 业务流案例（能源行业专家模型 + 10条样本运算）
+ **输入**：10 条已打标语料（S01电力规程/S02通用对话/S03故障案例/S04代码/S05学术数据/S06英文问答/S07声纹/S08热像图/S09未过滤网文/S10泛对话）+ 滑杆(专业70%) + 偏见降权
+ **处理（加权运算）**：
    - 专业类(S01/S03/S05)：条数3 × 权重1.2 = 有效3.6 → 占比最大
    - 通用对话(S02/S10/S06)：权重1.0，保持
    - 长尾(S07/S08)：权重0.5，兜底≥0.1%
    - 偏见降权(S09)：条数1 × 权重0.1 = 有效0.1 → 占比降到~1.1%
    - 降权让出的比例按权重重新分配补足100%
+ **输出**：最终投喂占比表 + 权衡对比图 + 偏见治理记录(S09 5%→1%) + 影响评估报告
+ **单样本级边界**：配比引擎可按"样本集(1000万，按标签聚合)"或"单样本(10条，每条直接给权重)"两种粒度运算，引擎与输入输出完全复用；10条是极限测试，能从单样本级处理说明更不怕大语料。

#### 承接与落地
+ L1：C3 数据配比引擎 ｜ L3：F1 数据配比引擎
+ 产出物：最终配比方案、权衡对比图、偏见治理记录、影响评估报告
+ 交接：此最终配比交给下游做实际数据投喂

## 12 章节关键认知汇总（2026-10-07 模拟问答确认）
### 1. 标签深度可变（不固定段数）
+ 标签 = 模态 + 一条**深度可变的树路径**（4段/5段均可）
+ 例：`文本-通用文本-新闻资讯-时政新闻`(4段) vs `文本-通用文本-新闻资讯-财经新闻-股市`(5段)
+ 判断标准：只要能**唯一、无歧义**落到某个细分类型即合法
+ 实现注意：类型树必须支持变深度路径，不能写死固定4层表结构（否则长尾深类型塞不进）

### 2. 高频≥30% vs 长尾覆盖100%：两个维度，不打架
+ **高频≥30%**(12.3-3)：核心常用场景的占比总和（量维度，"头部够不够强"）
+ **长尾覆盖100%**(12.3-4)：冷门类别是否被覆盖（有/无维度，"边缘是不是全在"）
+ 长尾只要"有一丁点"(甚至0.01%)就算覆盖，不去抢30%的盘面；一个管事、一个管有，互不冲突

### 3. 三个数：条数 / 权重 / 占比（最易混）
+ **条数**：该类实际有多少样本（客观，做分母）
+ **权重**：每条样本投喂时的份量（人为设定 0~1，乘在条数上）
+ **占比**：加权后占盘子的比例 = Σ(条数×权重) ÷ Σ(全部条数×权重)
+ ⚠️ **高频≥30%卡的是"占比"**（加权后的总占用量占比），不是纯条数占比，也不是单条权重
+ 权重影响占比，但对外挂的指标是"占比"这个最终数

### 4. 权重 = 采样频率 → 塑造模型参数
+ 权重本质是样本在训练中的出现频率（过采样/欠采样）
+ 权重1.0=正常每轮1次；0.5=半频（每2轮1次，梯度贡献减半、参数拉力减半）；0.1=约10轮1次；0=不学
+ 传导：权重→采样频率→梯度出现次数→loss加权项→参数更新被拉动→能力偏向高频样本

### 5. 数据源识别(12.1)有两个作用
+ **作用1 配比单位**：喂 12.1 自身来源级配比A/B（先识别"哪条从哪来"，才能算"网络/书籍/代码占多少%"）
+ **作用2 可信度依据**：供 C9/13.2 来源可信度评估（权威源信高、网络源信低）
+ 与 12.2 是两条并行识别线：12.1 管"从哪来"（喂配比A/B）、12.2 管"讲什么"（喂12.3细分配比），靠映射表关联

### 6. 数据源 → 可信度（C9）
| 数据源 | 可信度 |
| --- | --- |
| 内部规程/标准、科学文献 | 高 |
| 书籍/出版社 | 中高 |
| 网络文本/爬虫/论坛 | 低-中 |


### 7. 12 板块完整链条（电力巡检案例）
```plain
500万原始语料
  ↓ 12.1 数据源识别（标出来源：网页/书籍/规程/巡检记录/热像/声纹）
  ↓ 12.2 内容打标（每条挂"模态-一级-二级-细分"标签 + 数据源标签）
  ↓ 12.3 标签级细化配比（算占比、高频≥30%、长尾100%、动态迭代）
  ↓ 12.4 通用/专业权衡（调平"专业巡检 vs 通用常识"，防偏科）
  ↓
带配比比例的训练数据集 → 开训
```

### 8. 症状→章节定位（防偏科判断）
+ 缺**知识广度**（只懂一行/能源）→ 12.4-1 通用/专业配比权衡
+ 缺**小众场景**（不认冷门长尾）→ 12.3-4 长尾覆盖

### 9. 12.1 vs 12.2「看似矛盾」的本质：需求与方案混杂 + 正交维度（2026-10-07 飞鱼点破，最本质一条）
+ **发改委文档本身把「需求」和「实现方案」揉在一起**，是矛盾的根源，不是我们理解错。
    - 12.1 名义是个能力，实质是**实现 12 章配比的手段**（拿来源当加权依据）。
    - 12.2 是**内容治理**：给样本贴"它是什么"的客观属性。
    - 发改委却把"要配比"(需求) 和 "用来源识别来配比"(方案) 写成并列平行的两节 → 读起来像二选一 → 看似矛盾。
+ **两者不在同一个 x 轴**，本就是**正交维度**，不冲突：
    - 12.2 定了"它是什么"（属性/描述世界）
    - 12.1 定了"它从哪来、可不可信、在配比里算几份"（计量/决定配比）
+ **落地口径**：一个样本**两条标签都贴**——

```plain
内容类型(12.2)：文本 × 能源领域 × 政策文档
数据源(12.1)：   ← 官方网站 · 高可信
```

一条管属性、一条管配比采信，两级联动，共同服务 12 章整体配比目标。

+ **给审计/响应的说辞**：这两节不是二选一，是"内容分类定属性 → 数据源识别定可信度与配比"的两级联动。
+ **对发改委的批判性认知**：判断 12.1/12.2 时，要区分"任务书里它写了什么"(混杂版) vs "工程上实际该怎么实现"(正交版)，后者才是能落地的答案。

### 10. 分层定位定案：L2 能力完整 / L3 功能最少（2026-10-07 飞鱼拍板）
+ **三层分工**：
    - L1 能力域(C1-C9)：审计全覆盖，只多不少
    - L2 二级能力(12板块=25条)：骨架不缺+节点语义可区分，**保持完整 25 条不改**
    - L3 功能/配置(下一步)：**功能最少化**（砍到 3 个复合功能），这才是"最少"该落的地方
+ **结论**：能力清单不追求绝对最少（25~25能到18但不必），"合理范围内最少"=贴着审计边界不多不少；真正的功能最少化在 L3 实现
+ 已确认可合并项（28→18备用，但**不作为交付口径**）：12.1-4并入12.1-5、12.2-3/12.2-4并入12.2-2、12.2-8/12.2-9并入12.2-6、12.4-3并入12.4-2；12.1-2/12.2-5/12.4-4降为后台规则或字典
+ ⚠️ 提示：若给审计/评审看，保留 25 条更稳（每条对应一个可验收产出）

### 11. 高频核心标签集价值链：业务目标 → 圈选标签 → 前缀匹配捞取 → 30% 校验（2026-10-08 固化）
+ **高频核心标签集不是"样本集"，而是"标签节点路径的名单"**；存的是节点路径（类别），不是样本本体
+ **来源**：业务先定"这个模型要成为什么、哪些场景绝不能饿死"→ 到 12.2 打好的类型树上**圈选**对应标签节点 → 得到名单。**复用现有类型树，不产生新标签**
+ **高频 = 应该高频（目标），不是已经高频（现状）**：拿"当前占比最高的标签"当名单是错的（那是现状，起不到兜底）；业务按"要命场景"圈
+ **12 章配比层业务目标的三层**：
    - 模型定位（通用基座/行业垂直/混合）→ 定核心场景大类
    - 应用场景（对话/检索/创作）→ 细化核心场景
    - 商业上不能掉链子的场景（能源=安全规程/设备诊断、医疗=诊断/用药）→ 最重要的圈选依据
+ **捞取机制：标签路径 + 前缀匹配**——名单里存节点路径，捞取时把"路径以该节点为前缀"的样本（含其全部子树）都算命中核心场景
+ **校验**：核心标签加权占比 = Σ(命中核心样本条数×权重) ÷ Σ(全部样本条数×权重)，与 30% 下限比对
+ **完整链条**：业务目标（要什么）→ 类型树圈选（高核集名单）→ 前缀匹配捞样本 → 加权聚合→30%校验；与第9条呼应：业务目标=需求（要什么），配比=实现（怎么喂）
